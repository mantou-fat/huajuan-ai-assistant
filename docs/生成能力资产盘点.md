# 花卷 · 生成能力资产盘点（方向 B 的原材料）

> 来源：`D:\花卷归档\生成脚本`（109 个 `.py`）。目标：看清哪些能收编成"花卷的文档/材料生成长板"。
> 本轮为方向未定时做的基础盘点，任何方向都用得上。

## 一、能直接复用的生成器（核心资产 ✅）

| 脚本 | 产出 |
|---|---|
| `make_ppt*.py`（4 个：make_ppt / ime_v2 / merged / short） | PPT 生成（输入法成果 / RK3568 合并 / 精简版） |
| `make_docx*.py`（make_docx / make_docx_short） | Word 报告 |
| `md2pdf.py` | Markdown → PDF |
| `make_code_png.py` | 代码截图（带高亮） |
| `gen_resume*.py` | 简历生成 |

| `export_any_pdf.py` / `export_pdf.py` / `export_word_pdf.py` | PDF 导出 |
| `看图.py` | 借视觉模型读图（截图/文件/剪贴板） |
| `make_spl_project.py` / `make_stm32_project.py` | STM32 工程脚手架（zig+SPL 工具链） |

## 二、一次性 / 调试脚本（建议清理或归档 ⚠️）

`t_*.py`（约 20 个）、`probe_*.py`（约 15 个）、`test_*.py`（约 15 个）、
`try_*` / `check_*` / `verify_*` / `debug_*` / `fix_*` / `clean_*` / `purge*` / `split_bot.py` …

这些是当时排错留的。**不删不影响运行，但"别人看一眼"会觉得乱**。收编时统一移到 `_archive/` 或删掉。

## 三、隐患：源码副本 ⚠️

`生成脚本/bot.py`（95 KB）+ `生成脚本/app.py`（28 KB）是花卷主程序的**旧副本**，
和 `D:\python` 里的真身是**双份源码**，会漂移。收编时必须删掉副本或明确指向真正的仓库。

## 四、结论

1. **B 方向的"工厂"已经存在、且能打**：PPT / DOCX / PDF / 图 / 简历 / 电路图 / STM32 脚手架，全都有现成脚本。
2. **缺的不是"能生成"**，是三件事：
   - ① 一个**统一入口**（现在靠人/模型在中间传话，没有命令行或 API 包装）；
   - ② **一份文档 + 示例**（别人不知道这些脚本能干啥）；
   - ③ 让**花卷这个 agent 来驱动**它们（把生成器登记成花卷的工具 / 派给子 AI 执行）。
3. **收编三动作**：清一次性脚本 → 给生成器统一命名与参数 → 注册进花卷工具层。
